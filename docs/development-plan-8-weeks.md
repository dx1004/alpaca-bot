# Alpaca Ross small-account bot：8 周项目计划

> **2026-10-06 范围更新：**用户选择现阶段仅使用 Alpaca Basic/IEX 实时美股行情、Alpaca 新闻（须单独验证）及 Alpaca paper，暂缓 Webull 与付费实时 SIP。公开 Ross 规则不足以形成完整 $500／1× 版本时，用户接受另建明确标记的**混合策略**用于未来 paper，但必须独立通过来源、风险、数据、执行和版本冻结验收；不能把其他交易者规则记作 Ross 原规则或宣称 Ross fidelity。历史点时案例若无法补全，记录缺口，并在通过发布门槛后用预先登记的前瞻 shadow／paper 数据检验新版本；未来数据不能倒证旧案例。原计划中 Webull parity 工作是延后研究项，不再阻塞 Alpaca-only 路线。以下原始八周时间目标保留；门槛未过时按第 7 节如实判为研究／工程平台或 paper 未完成，不因日程而启动策略订单。

计划日期：2026-09-27。计划周期：8 周，严格拆分为 **4 周开发 + 4 周冻结 paper trade**。目标环境：美国个人用户、初始模拟本金 $500、Alpaca paper、全自动候选版本。策略目标：忠实实现一个证据明确且版本一致的 Ross Cameron small-account strategy；不以主观合理性、成本或开发便利替换原规则。

## 1. 两个月交付目标

第 4 周结束时必须完成开发、集成、故障测试和 fidelity 审核，形成不可在运行中随意修改的 release candidate。用户已选择免费优先：在对应运行账户的已对账本金达到 $1,500 并另行复核 SIP 前，第 5–8 周运行冻结的 `LIMITED_COVERAGE_PAPER`。它可提交 paper 订单，但必须记录免费来源、健康状态和 `NOT_SIP_EQUIVALENT` 覆盖差异，不能作为 Ross 全市场 fidelity 结论；不把第二个月当作继续开发策略的缓冲。

第 8 周结束时，目标交付：

- 一个可重复安装、配置验证严格、默认只能连接 Alpaca paper endpoint 的 Python 项目；
- 一份逐条可追溯的 Ross 规则台账和策略版本清单；
- 能采集并回放点时正确的市场数据、新闻、流通盘和账户事件；
- 对已经完全取证的 Ross 扫描、催化剂、入场、风险和退出规则进行确定性实现；
- 订单意图持久化、幂等提交、部分成交保护、断线恢复和对账；
- 冻结配置下的历史回放、影子运行和 Alpaca paper 运行报告；
- 一份 fidelity report，分别列出直接复现、功能等价映射、阻塞和未纳入的规则。

两个月的完成不代表盈利、可实盘或完整复刻 Ross 的全部人工判断。以下任一条件存在时，对应交易路径保持关闭：关键原规则未找到、版本冲突未解决、自动化语义不完整、所需行情/新闻不可用、无法证明 Alpaca 映射等价，或保护/对账测试失败。

## 2. 不可变开发原则

每个策略需求必须带一个 `rule_id`，并归入四类之一：

| 类别 | 含义 | 是否允许进入 paper 订单路径 |
| --- | --- | --- |
| `ROSS_DIRECT` | 一手来源清楚、版本适用、可直接机器执行 | 通过测试后允许 |
| `BROKER_EQUIVALENT` | Ross 行为明确，Alpaca 表达不同且已证明语义等价 | 通过等价性测试后允许 |
| `ENGINEERING_CONTROL` | 时间、审计、对账、故障保护；不改变策略选择 | 通过安全测试后允许 |
| `BLOCKED_RESEARCH` | 来源缺失/冲突、人工语义未定义、数据或券商能力不足 | 禁止新增风险 |

代码、配置和测试必须引用 `rule_id`。新增参数没有来源或明确的工程安全理由时，构建失败或配置拒绝；不得使用“临时默认值”让策略继续运行。

策略逻辑与以下内容分离：数据健康、账户能力、订单执行、运营成本和 paper/live 权限。安全控制可以否决 Ross 信号，但不能创造 Ross 没有的信号。

## 3. 目标项目结构

保持一个进程、少量模块，先避免微服务和不必要依赖。Alpaca API 接入优先复用官方 `alpaca-py`，版本锁定及 paper-only 适配器测试通过后才采用；下列模块负责本项目的点时证据、Ross 规则、安全边界和对账，不重复实现 SDK 已提供的 HTTP/WebSocket 客户端。选型与剩余边界见[现有工具复用评估](alpaca-existing-tools-review.md)：

运行数据和凭证不进入 Git。SQLite 作为订单/决策事务状态的首选候选；追加式压缩文件用于市场与新闻回放。最终选择在第 1 周用崩溃恢复和写入语义验证，不因目录草案自动冻结。

## 4. 八周执行计划：4 周开发 + 4 周 paper

### 第 1 周：开发——环境、Ross 规则冻结与数据能力

- 建立独立 `.venv`，验证并锁定 Python/依赖；配置 Ruff、严格 mypy、pytest 和 paper-only 配置拒绝规则。
- 建立 `source-registry`、`fidelity-matrix`、`strategy-version` 和 `rule_id` schema。
- 汇总 Ross small-account 一手来源，按日期、挑战版本、账户阶段和券商标记适用范围；股票筛选、新闻、形态、风险、加仓、止损、止盈、日亏损和停止规则逐条编号。
- 保留已实现的 Alpaca 只读 capability probe；评估官方 SDK 的只读调用能否在保持脱敏、超时和 paper endpoint 验证的条件下复用，核对账户字段、购买力、资产资格、交易时钟、市场数据和新闻权限。
- 建立逐数据集矩阵：实时/历史成交与报价、点时流通盘、历史 universe/退市、公司行动、原始新闻/修订；记录覆盖、字段、粒度、延迟、版本和保存/回放权限。
- 冻结候选 Ross 策略版本；冲突或缺失项进入 `BLOCKED_RESEARCH`，不混合版本补洞。

周门槛：环境可重复安装；每个拟实现策略字段均有来源或阻塞状态；实际能力来自只读响应；忠实策略所需但不可用的数据已成为显式关键阻塞。

### 第 2 周：开发——点时数据、回放、扫描器与新闻层

- 使用已验证的官方 SDK 接入行情/新闻 REST 与 WebSocket；实现统一事件 envelope、追加式事件存储、SQLite 决策状态、schema migration、心跳、重连、缺口和有限补数。SDK 重连不替代本地覆盖与点时验证。
- 分开前瞻日志回放和事后历史研究回放；保存持久化序号及原始/映射/指标/分类各自的实际可用时间，禁止未来新闻、修订数据和事后 ticker 映射泄漏。
- 实现已取证的 universe、价格、涨幅、RVOL 和流通盘规则；所有候选保存计算、版本和拒绝证据。
- 实现新闻去重、重发/修订、ticker 映射、来源状态、breaking/gap/continuation 分类及新闻与价格量反应连接。
- AI 只运行 shadow；其输出或故障不改变正式资格。正式新闻语义仍未取证时，新闻路径保持阻塞。
- 完成 DST、半日市、停牌、拆股、缺失流通盘、迟到/乱序和旧闻测试。

周门槛：相同输入产生相同结果；点时泄漏测试通过；IEX 只标记为工程 feed；缺原始历史版本的项目只完成合成契约测试，不冒充 fidelity 验收。

### 第 3 周：开发——Ross 入场、风险、退出与 Alpaca 执行

- 为已取证 Ross 入场形态建立独立状态机；实现对应仓位、止损、止盈/分批退出、日亏损和停止规则。
- 区分 Ross 规则、Alpaca 硬限制、压力测试假设和未解决差异。无来源的成交量比例、价差、流动性、费用或滑点参数不得进入正式下单计算。
- $500/1x 无法复现来源仓位时，研究无杠杆 Ross 版本；找不到则阻塞，不把缩仓自动称为等价。
- 在 exact-paper-host 验证后用已锁定的官方 SDK 实现 paper adapter 的 API 调用；本地仍负责持久化订单意图、唯一 `client_order_id`、订单状态机、WebSocket/REST 对账和重启恢复。
- 覆盖提交成功但响应丢失、重复/乱序、部分成交、撤单竞态、双退出腿成交、磁盘失败及异常反向持仓检测与处置。
- 开发月在基础 endpoint/账户/幂等安全检查通过后，允许使用隔离状态发送最小化的 Alpaca paper API 工程测试订单，以验证真实订单生命周期；这些不是策略自动订单，不进入策略表现或第二个月账户状态。
- 在本周结束前预登记第二个月的四周运行窗口、最低事件/候选样本、工程场景和 fidelity 留出集。

周门槛：每个订单候选都有 Ross 规则证明链；风险/退出无跨版本拼接；不重复提交或主动超量退出；无法确认订单状态时停止新增风险并保留保护/对账路径。

### 第 4 周：开发——端到端集成、故障测试与版本冻结

- 运行端到端历史/前瞻日志回放和实时 shadow，核对 scanner、新闻、策略、风险、订单各层接受/拒绝与延迟。
- 完成行情/新闻断流、API 限速、时钟偏差、停牌、半日市、重启、DB 锁、磁盘满和错误 endpoint 故障矩阵。
- 验证账户级依赖闭包：关闭盘前或其他形态不会静默改变拟运行切片的起始权益、持仓、未成交订单、连亏、日亏损或本金阶段。
- 隔离工程测试状态；完成测试成交清理、账户对账和经过验证的 $500 paper 起始快照。
- Astra Ultra 独立审核策略来源、自动化语义、数据等价和执行恢复；修复发现后重跑受影响验收。
- 冻结 `strategy_version`、`risk_profile_version`、数据配置、依赖锁、数据库 schema 和 paper release artifact。

开发完成门槛：所有 P0/P1 工程缺陷关闭；可安装、启动、停止、恢复和回放；默认拒绝 live；所有启用路径完成 fidelity 与账户依赖验收。若关键门槛未通过，不能为了按月启动交易而替换 Ross 规则；应明确报告开发阻塞，第二个月只能运行 shadow 或已证明隔离的研究切片。

### 第 5 周：Paper 第 1 周——冻结启动与基线

- 使用冻结 release、$500 起始权益和实际 Alpaca paper 购买力启动自动 `LIMITED_COVERAGE_PAPER` 运行；仅在全部启用免费输入健康、新闻与其他必需证据完整时提交 paper 订单，并为每笔记录 `NOT_SIP_EQUIVALENT`。
- 不调策略参数；记录候选、拒绝、新闻、风险、订单、成交、延迟、断线和对账证据。
- 每日只做数据/服务健康和账户对账；不因盈亏改变策略。
- 工程测试与正式 paper 使用隔离的账户状态和审计命名空间。

周门槛：连续运行和日终对账可重现；所有订单可追溯。正常日、故障日和停机时间全部保留在原窗口记录中，不得删除异常日。发现会影响行为的缺陷时停止新增风险，将原四周窗口标为中止/失败；修复形成新 release 后从头开始完整四周窗口，不能拼接。

### 第 6 周：Paper 第 2 周——稳定性与恢复证据

- 继续同一冻结配置和策略版本，收集正常交易日、无信号日及数据异常日。
- 验证计划内重启、断线恢复、缺口补数和订单对账；不会为了制造样本而触发交易。
- 报告数据覆盖、新闻延迟、候选漏失迹象、订单状态差异和保护状态。

周门槛：恢复不改变既有决策；故障期间无静默新增风险。任何改变策略、数据资格、风险、订单行为或证据完整性的修复必须形成新 release，将原窗口标为中止，并从头开始新的完整四周窗口；不能只重跑部分日期或拼接结果。纯观测性修复也必须留痕并证明不改变行为。

### 第 7 周：Paper 第 3 周——样本积累与独立中期审核

- 继续冻结运行；比较实际候选与保存的 Ross 规则证明链。
- 对新闻判断、RVOL、形态、风险和退出进行盲抽样核对；AI 仍保持 shadow，除非它在开发月已完成正式 fidelity 验收。
- Astra Ultra 做不改变策略的中期审计，识别资料偏差、数据覆盖缺口和执行异常。

周门槛：中期发现只分为工程缺陷、fidelity 缺口和正常策略结果；禁止依据 paper 盈亏调参。关键缺陷触发停止、修复、新版本和新的完整四周窗口，原窗口保留并标为中止。

### 第 8 周：Paper 第 4 周——完成窗口与最终报告

- 完成预登记的四周 paper 窗口；没有达到最低自然事件/候选样本时明确判定证据不足。
- 生成 fidelity、数据覆盖/延迟、新闻一致性、订单恢复和 paper 运行报告。
- 分开报告交易结果、固定运营成本、工程可靠性和策略一致性。
- 对全部交易和拒绝抽样回放；确认未使用未来数据、未混合版本、未在运行中调整策略。

最终门槛：未解决 fidelity 差距对应路径保持关闭；四周运行不足或因修复重置后未完成窗口时，交付状态写“paper 试跑未完成/证据不足”；不自动进入 live。

## 5. 关键路径与并行工作

开发月关键路径：策略版本取证与数据能力 → 点时回放/扫描/新闻 → 形态/风险/执行 → 端到端故障验收与 release 冻结。Paper 月关键路径：冻结启动 → 连续运行与恢复 → 中期审核 → 四周窗口报告。

可并行项：

- Ross 资料研究可与环境搭建、事件 schema 开发并行；
- 新闻样本整理可与市场采集器开发并行；
- fake execution adapter 可与只读数据探测并行；
- 文档、fidelity matrix 和测试证据随每周改动同步更新，不能留到第 8 周补写。

不得并行越过的依赖：

- 未冻结规则版本前，不实现会选股或改变风险的默认参数；
- 未验证点时回放前，不做策略表现结论；
- 第 4 周 release gate 未通过前，不提交正式策略自动 paper 订单；开发月只允许隔离、最小化且不计入策略结果的 API 工程测试订单；
- Paper 月中任何行为性代码变更都生成新版本、终止原窗口并从头开始完整四周窗口；
- 未通过新闻一致性前，不让 AI 进入候选批准路径。

## 6. 测试与验收集合

最低测试层次：

1. **单元测试**：指标、状态转换、风险计算、时间和 schema。
2. **契约测试**：Alpaca 请求/响应、WebSocket 事件、feed 与 endpoint 验证。
3. **回放测试**：真实事件顺序、迟到/乱序、无未来数据、版本可重复。
4. **故障测试**：超时、断流、重启、磁盘和不确定订单确认。
5. **Fidelity fixtures**：Ross 已公开案例的输入与预期判断；只验证能够从证据确定的部分。
6. **Paper 验收**：真实 endpoint 的订单生命周期和恢复，不以盈利作为工程通过条件。

持续检查目标：`ruff check`、`mypy --strict`、`pytest`、依赖锁一致性、秘密扫描和配置 schema 验证。具体工具和版本在第 1 周兼容性验证后冻结。

## 7. 两个月结束时的判定

| 结果 | 判定 |
| --- | --- |
| 工程、所选版本全部必要行为、账户级依赖闭包及 fidelity 门槛通过，且达到预登记 paper 窗口/样本 | 交付 Ross 策略 paper 候选版；继续冻结前瞻 paper 收集 |
| 工程通过，但行情/新闻/人工规则无法等价 | 交付研究与工程平台；相关交易路径保持关闭，不称完整策略 |
| 执行恢复或保护语义未通过 | 不提交自动 paper 订单；交付回放/shadow 系统并继续修复 |
| 工程与 fidelity 门槛通过，但第 8 周前瞻窗口或自然样本不足 | 交付可继续运行的冻结候选版，状态为试跑未完成/证据不足 |
| Paper 有利润但 fidelity 或工程门槛失败 | 仍判定失败；利润不覆盖规则偏差或安全缺陷 |
| Paper 无利润但工程与 fidelity 门槛通过 | 如实报告；样本期不足时不宣称策略失效或有效 |

第 8 周不是 live 决策点。至少还需要预先登记的更长前瞻 paper 窗口、足够样本、数据成本后的结果、真实成交压力评估和独立实盘授权。

## 8. 当前已知的计划风险

- Ross 公开资料可能不足以定义所有人工判断，尤其新闻质量、Level 2/Time & Sales 读取、加仓和动态退出。
- 2017/2019/2025 挑战规则与通用课程可能冲突，不能拼接赶工。
- Alpaca $500 账户的 1x 购买力无法复现历史 offshore/CMEG 杠杆；信号策略可能可复现，历史仓位与收益路径不可复现。
