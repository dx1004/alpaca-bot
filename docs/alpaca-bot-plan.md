日期：2026-09-27。状态：已确认美国、$500、本地新 Git、全自动、paper 优先及 Ross Cameron 策略来源；正在把原始规则转为明确规格。不是可执行策略，也不是盈利结论。

用户已确认 Warrior Trading 的 Ross Cameron、来源项目 invest-project-variation 和 Astra Ultra。要求风险、杠杆与退出按 Ross small account strategy，而不是自行设计另一套风险偏好。已使用独立 `gpt-6-astra` / `ultra` 子代理研究原始资料；不同版本之间不能静默拼接。项目规则继承与环境检查见 `../AGENTS.md`、`environment-baseline.md`。

最新决策：所有策略规则默认采用 Ross 已明确、且适用于对应版本的原始规定，无需逐项再请用户批准。只有原始资料缺失、冲突或不足以自动执行时才进一步研究；先用 Astra Ultra 和一手来源确认适用性，仍存在真正的用户选择才提问。该授权不是在相互冲突的版本之间自动选中某一套，也不覆盖券商限制或付费授权。

## 1. 目标、范围与完成标准

目标是设计个人使用 Alpaca Trading API 的小账户股票交易系统，能够解释每次候选、拒绝、下单意图和结果，并可回放验证。

本次交付包括规则继承、环境基线、来源研究、建议架构、实施阶段与待决策表。未安装应用依赖、访问账户、发送模拟或实盘订单、购买数据或部署服务。开发目标已确定为全自动 paper，初始资金 $500；交易时段和原始资料未定义的自动化语义仍需明确。用户询问数据预算，尚未授权付费订阅。

当前目标不包括复制 Ross 的收益曲线；目标是尽可能忠实实现一个证据明确、版本一致的 Ross small-account strategy。未解决的人工判断或资料缺口必须标为未实现/阻塞并继续研究，不能先用“合理替代”填入。只有通过逐项一致性验收后才可称为该版本的实现；验收前报告为“Ross strategy fidelity research”，并明确已复现与未复现部分。

### Strategy fidelity contract

每条策略行为只能走以下三条路径：

1. **原规则直接实现**：有适用的一手来源，语义足以机器执行，按原规则实现并保存版本证据。
2. **功能等价的券商/工程映射**：原行为明确，但 Alpaca 接口表达不同；映射必须保持选股、时机、风险和退出结果的语义，并用测试证明等价，不能仅凭“看起来合理”。
3. **阻塞并研究**：资料缺失、不同版本冲突、Ross 使用人工判断、所需数据不可获得，或无法证明等价。该路径不得开新仓，先用一手来源和 Astra Ultra 研究；研究仍不能解决时再向用户提出真实的取舍。

禁止第四条路径：为了成本、开发便利或主观合理性，静默创建一个 Ross 没有说明的参数或替代规则。

## 3. Alpaca 适配：已核对的约束

1. **日内保证金规则更新。** Alpaca 公告称 2026-06-04 已上线新框架，并要求从旧 PDT 字段转向当前 `buying_power`。因此不硬编码旧的 $25,000 / 五日交易次数规则。FINRA 允许券商分阶段实施，不能把 Alpaca 的时间推广到所有券商；用户具体账户仍需核实。[Alpaca 公告](https://alpaca.markets/blog/finra-retires-the-pdt-rule-introducing-alpacas-new-intraday-margin-framework/)、[FINRA Notice 26-10](https://www.finra.org/rules-guidance/notices/26-10)
2. **账户类型不能靠名称猜。** Alpaca 支持页说明其账户按 margin 开立；不使用借款不等于现金账户。地区、账户权限、个股保证金和可用购买力须读取实际账户能力再验证。[账户说明](https://alpaca.markets/support/alpaca-cash-accounts)
3. **行情不是同一种覆盖。** 官方当前列出 Basic 为 IEX、30 个 WebSocket 股票订阅；Algo Trader Plus 为 $99/月、完整美股交易所覆盖。我们的判断：全市场动量筛选不能将单交易所成交量当成全市场量，免费路径只能先验证受限范围的工程流程。数据预算未定，不订阅、不自动降级后继续交易。[数据套餐](https://docs.alpaca.markets/us/docs/about-market-data-api)
4. **盘前的保护方式不同。** 当前扩展时段接受符合条件的 limit 订单；bracket 不支持扩展时段，而且退出腿在入场完全成交后才激活。快速行情还有退出腿竞态风险。我们的设计必须单独覆盖部分成交、撤单与保护状态，不能把接受 bracket 当成已受保护。[订单文档](https://docs.alpaca.markets/us/docs/orders-at-alpaca)
5. **Paper 不能证明低流通盘执行能力。** 模拟不覆盖真实排队、延迟滑点与市场冲击，成交数量也不按 NBBO 可见数量约束。需另做保守成交压力回放；paper 的主要作用是验证接口和状态恢复。[Paper 文档](https://docs.alpaca.markets/us/docs/paper-trading)

以上为查询日的公共文档证据，尚非账户集成实测。行情、新闻、流通盘和市场深度的授权与历史覆盖仍未验收；SIP 顶层报价不能当作完整 Level 2。

## 4. 已确认目标与待冻结的策略规格

确定目标：美国用户、$500、全自动、paper 优先。第一阶段可以只实现基础设施和已经完全取证的策略切片，但不得把切片改称完整 Ross small-account strategy。做多范围、入场形态、交易时段、仅整股、持仓数与收盘清仓语义，均须由所选 Ross 版本和券商等价性证据明确；未明确部分保持阻塞。

券商硬约束：Alpaca 当前文档规定股票账户净值低于 $2,000 时仅有 1x 购买力，不能借款交易或做空。因此 $500 paper 必须模拟这一约束，不能使用默认大额模拟余额或 CMEG 的杠杆。[Alpaca margin 文档](https://docs.alpaca.markets/us/docs/margin-and-short-selling)

流水线：

市场与资产资格 → 宽范围发现 → 按需补充行情/流通盘/新闻 → 确认候选 → 已取证的 Ross 入场形态状态机 → Ross 风险/退出规则与不可超越的券商安全约束 → 订单管理 → 对账与审计。

- 股票进入 watchlist 不是入场信号。交易资格、数据完整性和策略条件独立判断。
- 在当前时刻可得的数据上筛选，不能用收盘涨幅、未来新闻或修订后的流通盘倒选历史赢家。
- 为每项阈值记录单位、来源、比较边界、有效期与缺失值策略。
- 必须定义 RVOL 的分母、回看天数、同时间段比较方式及盘前是否计入；不同口径不能共用阈值。
- 定义冲高起点、回调最小/最大持续时间、最大回撤、缩量窗口、突破参考价、信号有效期、允许追价和重复入场规则。
- 明确使用已收盘 bar 还是 intrabar 触发。普通一分钟 OHLC 无法恢复秒级路径；同 bar 同时碰止盈止损时不得挑有利顺序。
- 新闻候选必须保存首次可见时间和证据来源。模型可做有证据的结构化分类；`CATALYST_ALIGNED` 仍须通过确定性的来源、时间、市场确认、形态与风险门槛。模型不批准交易或风险豁免；无法确定时保留未确认状态。完整规则见 [`news-layer-spec.md`](news-layer-spec.md)。
- 流通盘必须有 as-of 时间、来源及公司行动处理；缺失、过时、拆股不一致均不可默认为合格。
- 全自动模式中，“强”“浅”“市场热度”“阻力小”必须明确成可测试定义。未定义或证据不足时跳过，不能默默改成人工确认每笔交易。

## 5. 风险和订单底层逻辑

### 仓位与风险预算

仓位计算必须先采用所选 Ross 版本的单笔风险规则，再受 Alpaca 实际购买力、整股和不可超越的安全/流动性上限约束。向下取整、费用和压力滑点只用于确保实际风险不超过 Ross 规则及券商约束，不能反向扩大仓位、止损或风险预算来追求原目标金额。

还需扣除现有持仓和未成交订单占用；部分成交与待撤订单继续占用预算。价格、金额采用 Decimal 或整数精度表示。止损价不是可保证的最大亏损；跳空、停牌与无买盘情形必须独立压力测试。

用户已要求按 Ross small-account 原始规则推导单笔风险、日内止损和退出，不再把所有参数作为自由偏好重新提问。应记录具体来源及版本；若资料存在冲突，只针对冲突提出选择。券商购买力优先于教材杠杆。日内损失口径必须说明已实现/未实现、费用和外部入出金处理；原始资料没有给出的自动化细节保持待定义。

### 订单状态与恢复

建议状态：观察 → 条件成立 → 意图已持久化 → 提交结果待定 → 已接受/部分成交/全部成交 → 退出处理中 → 已平仓并对账；拒绝、取消、过期、异常另有明确状态。

- 唯一 `client_order_id` 与持久化意图关联；提交超时后先查询核对，禁止盲目新建第二笔。
- 单一账户执行写入者；事件去重并处理乱序。WebSocket 通知与 REST 对账共同维护状态，断线重连不直接恢复开仓。
- 撤单请求不代表撤单成功，保护单也不能因日内停机一并误删；先核实实际成交数量与剩余订单。
- 部分入场保护、部分退出后剩余数量、撤改单竞态、父子订单联动、意外反向持仓必须纳入测试。未解决保护语义时禁止部署该路径。
- 行情陈旧、状态不明、磁盘写入失败、风险触发：停止新增风险，保留可用保护并报警。已有仓位的减仓/退出行动由事先批准的故障处置策略控制，不能简单用 `NO_ACTION` 放任风险。
- 紧急停止拆成停止入场、撤销未成交入场、管理已有仓位、人工处理；不是一个未经确认的“取消全部订单”按钮。
- 盘前若采用应用层限价退出，断网或进程崩溃时可能失去管理能力，且限价不能保证成交。必须先明确可接受的处置方式，再开发该分支。

所有事件记录交易所时间/事件时间、接收时间、处理时间；内部使用 UTC，交易日与时段通过 `America/New_York` 和交易日历计算，覆盖夏令时与半日市，不硬编码固定 UTC 偏移。

## 6. 建议技术结构与基础环境

建议以单个 Python 服务和少量明确模块开始；库版本经过兼容测试后锁定。

| 模块 | 职责 |
| --- | --- |
| config / schemas | 区分未批准与可执行配置；校验环境、单位、版本与未知值 |
| market_data / reference_data | 订阅、补数、行情质量、点时流通盘与新闻证据 |
| scanner / strategy | 发现候选、确定性特征与形态状态机 |
| risk | 资金/仓位/流动性约束和不可覆盖的否决 |
| execution / reconciliation | Alpaca 适配、唯一订单意图、生命周期与恢复 |
| journal / replay | 持久事件、证据索引、可重复回放 |
| health / operator | 心跳、数据延迟、异常告警、人工控制 |

建议轻量本地存储：SQLite 保存事务状态，按需用 Parquet 保存市场回放数据；具体存储属于提案，部署与数据规模确定后验收。运行数据与凭证独立于 Git；不在两个位置无必要地重复写完整载荷。

常驻交易路径使用确定性代码，不等待 LLM 网络调用。Astra Ultra 用于设计研究/独立核查；Ollama 仅按共享规则做离线数据归纳，不参与交易、执行或对账决策。云主机位置、成本和服务守护等到部署目标确认后决定。

## 7. 分阶段交付与验收门槛

| 阶段 | 交付物 | 进入下一阶段的证据 |
| --- | --- | --- |
| A：冻结需求 | 选定原始版本、参数字典、用户决策记录、账户与数据能力表 | 本金/风险/时段/执行方式已确认；没有未定义的执行关键参数 |
| B：环境与离线核心 | 独立依赖锁、scanner/strategy/risk、合成事件回放 | 静态检查与关键测试通过；错误或未知数据可靠阻止开仓 |
| C：只读数据验证 | 真实数据采集、延迟与缺口报告、候选证据 | 覆盖与授权可用，新闻/流通盘可追溯；策略未借用未来数据 |
| D：成交与恢复验证 | 压力回放、paper adapter、订单状态机 | 超时、重启、乱序、部分成交、停牌/时段切换等场景有确定结果；无重复暴露或静默失去保护 |
| E：冻结前瞻 paper | 固定策略版本、预先登记窗口与判据、报告 | 工程可靠性与策略表现分开评估；样本不足明确写不足 |
| F：实盘决策 | 独立评审、账户实测、明确风险与故障预案 | 另行明确授权；不得从 paper 达标自动切到 live |

研究需包含失败/无信号日、退市或公司行动影响，使用时间顺序开发/验证/留出，记录尝试过的参数版本，避免反复优化留出集。对照可包括不交易和同股票池的简单突破；报告成本后期望、回撤、尾部损失、成交敏感性、交易数量及不确定性，不以某个胜率或固定几天“赚钱”作充分依据。验收窗口、样本量和数值门槛在运行前确定。

关键测试至少覆盖：陈旧或缺失报价、零流通盘、未来新闻、拆股、休市/DST、重复信号、购买力变化、负/零止损距离、POST 已成功但响应丢失、部分成交后进程退出、撤单同时成交、退出腿竞态、断线恢复、磁盘失败以及误配置 live endpoint。

## 8. 用户已确认与剩余决策

已确认：来源项目、Ross Cameron、Astra Ultra、美国、初始 $500、全自动、paper 优先、风险/退出遵循原始策略、新建本地 Git（已完成）。用户已授权在 SIP 之前先使用其他可验证的免费来源，满足部分最低功能后运行有限覆盖的自动 paper；该运行必须标记为 `NOT_SIP_EQUIVALENT`，不作为全市场 Ross fidelity 验收。只有记录到对应运行账户的已对账本金达到 $1,500 后，才重新评估 $99/月 SIP。该门槛不自动订阅、不会改变 Ross 策略或风险版本，也不授权 live。

## 9. 数据预算建议

### 交易本金与工具成本必须分账

Ross 的 small-account challenge 不是“全部资源只有 $500”的实验。2017 年挑战最初存入 $700，平台费扣除后交易余额为 $583.15；挑战总结显示其机会发现依赖 Trade Ideas 扫描器，并辅以交易社区、StockTwits/Twitter，后续明确使用 eSignal 图表/报价和专业执行平台。[挑战首日](https://www.warriortrading.com/small-day-trading-account-challenge/)、[第 44 天总结](https://www.warriortrading.com/day-44-100k-challenge-8871-40-breaking-100k-mark-ep-48/)、[第 59 天工具说明](https://www.warriortrading.com/day-59-583-challenge-114-34/)

Ross 后来明确把 monthly operating costs 与交易账户 initial startup capital 分开讨论。他当时举例约 $170/月图表软件、约 $40/月实时数据，并粗估约 $300/月营运费；这些是 2020 年的示例，不能倒推为 2017 年逐项账单。[Ross 对营运成本与交易本金的区分](https://www.warriortrading.com/day-trading-business/)

因此，本项目把 `trading_equity`、`research_data_cost` 和 `production_operating_cost` 分开记录。$500 是已确认的模拟交易本金；它既不自动授权额外预算，也不能被解释成包含所有研究工具的总预算。Alpaca $99/月是供应商行情方案，不是 Ross 策略的资本阶段或历史费用。是否启用应由数据验证阶段和经济可行性决定，不能虚构一个“Ross 达到某本金后才订阅”的门槛。

| 阶段 | 当前可核实费用 | 能验证什么 |
| --- | --- | --- |
| 离线开发 / Basic 工程联调 | 行情订阅 $0/月 | 合成回放、状态机与有限 IEX 覆盖；不作为完整 Ross 扫描器或策略收益验收 |
| 本金未达 $1,500 的有限覆盖 paper | 行情订阅 $0/月 | Alpaca Basic/IEX 实时行情和 paper 执行；仅使用已验证的免费候选/新闻源。可提交 paper 订单，但每笔均标记 `NOT_SIP_EQUIVALENT`，不得作为全市场 Ross fidelity 结果 |
| 本金达到 $1,500 后的 SIP 复核 | Algo Trader Plus 行情 $99/月 | 仅在用户复核后验证 SIP 覆盖与更大订阅范围；仍需验证新闻、流通盘和历史可用时间 |
| 完整数据总预算 | $99/月加尚未核定的补充数据成本 | 取决于账户新闻权限、可用流通盘来源及是否需要 Level 2；不能把 $99 宣称为全包 |

价格证据：[Alpaca 当前数据套餐](https://docs.alpaca.markets/us/docs/about-market-data-api)。API 新闻由 Benzinga 提供，但不能用早期免费 beta 公告承诺当前账号永久免费；先核对权限及覆盖。[新闻文档](https://docs.alpaca.markets/us/docs/historical-news-data)

### Webull 首选候选（2026-09-28 用户偏好）

用户已选择 Webull 作为 Alpaca SIP 之外优先验证的扫描与行情候选；Alpaca 仍是当前 paper 执行目标。该偏好确定验证顺序，不预先判定 Webull 与 SIP 或 Ross 的 Trade Ideas 工作流等价。

Webull 官方 OpenAPI 当前提供 `PRE_MARKET` 涨跌榜、价格涨幅、当日成交量、10 日相对成交量及最多前 200 名结果，另有 Top Active、股票快照、历史 bars、实时 MQTT 行情和 watchlist 新闻摘要接口。生产 screener 的集中限速页列为每接口 60 次/60 秒；单独接口页仍写 600 次/分钟，属于必须以较低值设计并通过账户实测或官方确认解决的文档冲突。[涨跌榜接口](https://developer.webull.com/apis/docs/reference/get-gainers-losers/)、[限速](https://developer.webull.com/apis/docs/rate-limits/)

这还不能证明完整替代：官方要求美国股票 OpenAPI 使用独立的 non-display Nasdaq Basic 或 Nasdaq TotalView 订阅，手机/桌面订阅不通用；当前公开资料没有证明该报价/成交口径是 CTA/UTP 全部交易所的 SIP 合并流，也未确认全流通盘、Ross 所需原始新闻时间或实时 streaming symbol 总上限。[行情权限](https://developer.webull.com/apis/docs/market-data-api/overview/)、[实时流](https://developer.webull.com/apis/docs/market-data-api/data-streaming-api/)

因此 W1/W2 首选验证路径为：Webull server-side screener 发现候选 → 对候选补充实时行情、点时流通盘和原始新闻 → 与可核实的 SIP/基准样本对照盘前涨幅、RVOL、候选召回率、排名稳定性与延迟。任何关键字段、授权、覆盖或容量未通过时，对应 Ross 实时 paper 路径保持阻塞；不得把 Nasdaq Basic 的证券范围覆盖解释为全交易场所 SIP 覆盖。

先以 $0 做工程阶段，不代表用 IEX 替代 Ross 的全市场发现逻辑。用户已授权：在对应运行账户的已对账本金达到 $1,500 前，采用有限覆盖的自动 paper 路径。默认市场与执行输入为 Alpaca Basic/IEX；候选发现、新闻和流通盘各自只能接入经能力探测通过的免费来源，缺一项或不健康就阻止新开仓。所有输出固定标记 `NOT_SIP_EQUIVALENT`，不得产生“Ross 全市场策略 paper 已通过”的结论。达到门槛后也只触发一次人工 SIP 复核，不自动订阅、不切换策略版本、不变更仓位或杠杆。若证据确认所选版本依赖全美市场的实时扫描，则完整策略的实时 paper 验收仍必须使用功能相当的覆盖。报告同时列出有限覆盖 paper 的结果、覆盖差距与扣除固定研究费用的经济结果，不通过改变 Ross 规则或提高风险来抵消订阅费。

具体阶段逻辑：

1. **$0 `LIMITED_COVERAGE_PAPER` 阶段**：使用 Basic/IEX、已验证的免费候选/新闻/参考源运行纸盘；只在全部启用输入健康且证据完整时提交 paper 订单。记录每个来源、覆盖差异和拒绝理由，不产生“Ross 全市场策略已通过”的结论。
2. **$1,500 后的完整数据复核阶段**：只有已对账本金达到 $1,500、代码/回放/失败测试已就绪且用户重新确认后，才考虑购买一个明确期限的 SIP 月份，记录其对候选发现、RVOL、排名和新闻关联的增量价值。
3. **持续运行决策**：分开报告策略交易结果与固定运营成本。如果所选 Ross 版本经取证确实要求该覆盖，那么缺少覆盖时应停在工程/研究状态，不能以成本为由换成 IEX 后仍称忠实策略；是否承担持续成本是后续真实取舍，不会因账户余额触及任意数字自动购买。
4. **新闻独立验收**：SIP 解决成交/报价覆盖，不自动解决新闻。新闻权限、来源、延迟和漏报按 [`news-layer-spec.md`](news-layer-spec.md) 单独测试。

## 10. $500 风险来源研究与规则候选

Astra Ultra 的补充研究未找到一份完整、自洽、可直接自动执行的 $500 风险与退出规格。以下两套来源不能未经说明混合：

| 来源版本 | 规则 | $500 的含义 |
| --- | --- | --- |
| [2025 toolkit 第4页](https://cdn.warriortrading.com/warriortrading.com/assets/2025-Small-Account-Tool-Kit-1013.pdf#page=4) 百分比表 | 每笔约5%账户风险、每笔约10%账户盈利目标、每日10%最大亏损 | 换算为 $25 风险预算、$50 目标、$50 日亏损线；这是按表缩放，不是已证实的历史 $500 参数 |
| [同一资料第3页](https://cdn.warriortrading.com/warriortrading.com/assets/2025-Small-Account-Tool-Kit-1013.pdf#page=3) 固定额示例 | $50 每笔风险、$100 目标、$100 日亏损、连续三笔亏损停止 | 不自行缩半，也不把“三连亏”自动并入百分比表 |

[2019 年回顾](https://www.warriortrading.com/2019-year-in-review/) 中的 $500 挑战使用了另一券商的4倍杠杆；与本项目 Alpaca $500 的1倍购买力不等价。

此前要求用户直接选择百分比表或固定额表的问题已由“全部采用 Ross、缺失再研究”的新指令取代。两表的适用性列为研究缺口，不能把广义策略授权当成对5%/10%版本的单独选择。日初净值快照、费用/浮亏计入、复位时间和总回撤阈值是需要研究的自动化语义，不能声称来自 Ross。百分比表的 MACD、缩量和急跌反转退出也没有完整机器阈值；不套用其他 bull-flag 或 micro-pullback 教材的分批退出比例来填空。

风险预算是上限，不是必须亏损或投入的金额。例如 $500、$5/股、结构止损距离 $0.05，忽略费用最多100股，结构风险只有 $5；不能扩大止损或使用不存在的借款来凑足 $25。相同原因下，账户10%盈利目标不等于每笔都能达到的2R退出价，也不是交易配额。

## 11. 本金增长与回撤的阶段管理

用户要求支持多阶段。设计上拆分三个独立维度：

1. **仓位随净值变化**：若选定百分比版本，资金增长只改变风险预算和可买股数；不意味着更换入场形态。
2. **券商能力变化**：Alpaca 股票借款功能的 $2,000 净值门槛。用户已确认 $2,000 以下坚持无杠杆，达到门槛后可以研究并接受有原始依据的 Ross 杠杆版本；这不是触线就自动借款的指令。实际可用倍数须由账户权限、`multiplier`、实时 `buying_power` 和股票保证金要求共同确认。
3. **策略版本变化**：只有找到对应原始依据、完成独立验证并预先批准切换条件，才可自动切换。当前没有证据支持凭空建立 $500/$1,000/$5,000 各一套 Ross 策略。

| 阶段 | 定位 | 进入/保持条件 | 不会自动发生的变化 |
| --- | --- | --- | --- |
| P0 | 离线与接口工程 | 模拟本金设为 $500，验证数据、风险与恢复 | 不通过工程测试宣称盈利 |
| P1 | $500 起步的冻结前瞻 paper | 选定来源与自动化语义、数据覆盖验收通过，模拟真实1x购买力 | 资金增加不自行切换策略 |
| P2 | 同版本扩大仓位 | 预先批准的净值口径、流动性/成交容量测试通过，风险预算仍受购买力和容量限制 | 不把名义资金增加视为策略有效性证据 |
| P3 | $2,000 及以上的杠杆 Ross 候选版本 | 已对账净值达到券商门槛、账户实际获准杠杆、选定 Ross 原始版本并验证其风险/退出规则；另行比较1x与获准倍数的 paper 压力结果 | 不因触及 $2,000 自动借款、套用 CMEG 的6x或改变退出 |
| P4 | 更高资金/另一策略版本 | 有明确来源与独立回放/前瞻证据；预先批准切换条件 | 不虚构 Ross 的资金分段或自动进入 live |

建议阶段控制器单独维护 `capital_stage`、`strategy_version`、`risk_profile_version` 和 `broker_capabilities`；这些是设计字段，当前尚未实现。

[Warrior Trading 的 2025 挑战记录](https://support.warriortrading.com/support/solutions/articles/19000168902-small-account-challenges-at-warrior-trading)说明 Ross 以 $2,000 在 CMEG/DAS 开始，最初可用 6x，首周获利后重置到 $2,000 并改用无杠杆。他的[现金账户文章](https://www.warriortrading.com/can-you-trade-in-a-cash-account/)另述 $2,000 Webull 情境；两者不可合并成同一套仓位规则。按 2026-09-30 可查的 [Alpaca 股票保证金说明](https://docs.alpaca.markets/us/docs/margin-and-short-selling)与[账户字段说明](https://docs.alpaca.markets/us/docs/account-plans)，低于 $2,000 为1x；达到门槛后普通保证金账户通常为2x，获准账户日内最高可为4x，但并非 CMEG 的6x。股票本身的保证金要求还可能缩小实际购买力。此处只确定研究与阶段边界，未冻结 P3 的策略或倍数。

- 阶段评估采用一致的权益快照和入出金处理。避免未实现浮盈瞬时触发升级；快照时点与是否计入未实现盈亏必须在运行前冻结。
- 建议仅在无持仓、无待处理订单且对账一致的边界升级，以免交易中途改变止损/目标。具体时间、维持天数和缓冲区待定，不能临时拍数字。
- 升级要求不只是余额：包括数据完整、执行稳定、预登记样本/表现判据、流动性容量和故障验证。净值增长本身不代替这些证据。
- 预先规定降级与停止条件，并使用不同的升级/降级边界防止频繁切换。能力丧失或风险触发时先阻止新增不合规风险；已有仓位仍按批准的处置规则保护。
- 没有已批准的下一阶段时保持当前可用版本，受当前资金和券商约束继续运行或暂停；不得自行挑选新策略。
- 所有阶段变更保留旧/新版本、权益依据、能力快照、触发原因及时间，供回放重现。paper 与 live 使用独立阶段状态。
