The current [dedicated rate-limit table](https://developer.webull.com/apis/docs/rate-limits/) lists relevant scanner/snapshot/tick and stream-management endpoints at 30 requests/60 seconds in sandbox and 60/60 seconds in production. The [Market Data FAQ](https://developer.webull.com/apis/docs/market-data-api/faq/) instead says 300 HTTP requests/60 seconds and no subscribe/unsubscribe limit; a gainers reference states 600/minute. Treat capacity as **conflicting documentation, not a measured allowance**. The same FAQ says subscription-dependent sandbox stock data is 15 minutes delayed absent a production real-time entitlement.

No account-free executable test path was verified: [general getting started](https://developer.webull.com/apis/docs/getting-started/) advertises shared test accounts, but its linked [SDK/Test Accounts page](https://developer.webull.com/apis/docs/sdk/) points to an account/application flow. The account and contract questions cannot be closed by parsing public pages alone.

**Disposition:** Webull is a documented non-display API candidate. It is not verified free, account-enabled, licensed for the intended stored evidence, CTA/UTP SIP-equivalent, or complete for Ross's premarket scanner, float and raw-news needs. Keep the dependent real-time Ross path disabled. Next evidence would be a redacted OpenAPI entitlement/contract and actual quote for this account, then bounded read-only field, ranking, timing and coverage tests; none authorizes a purchase or strategy order.
